# bench: browser agent vs clify agent (20 tasks, 11 public sites)

Same model (Claude Opus 5.5 via Claude Code `-p`), same task prompt, four ways to reach the web:

| Mode | Setup |
|---|---|
| `browserUi` | Playwright MCP over CDP to headless Chromium, `browser_evaluate` / `browser_run_code_unsafe` disabled (clicks, typing, page snapshots: how consumer browser agents work) |
| `browser` | Same, full Playwright MCP incl. page JavaScript (the strongest browser baseline) |
| `cli` | Bash only, clify on PATH, no curl/WebFetch |
| `curl` | Bash with curl, jq and python3, plus WebFetch and WebSearch; no clify, no browser (an agent calling the sites' pages and public APIs itself) |

These are easy public read-only tasks: 10 of the 20 tasks run on 4 scraping-practice sites (books.toscrape.com, quotes.toscrape.com, scrapethissite.com, webscraper.io), the other 10 on 7 real sites. The CLIs for these 11 sites were hand-written for the benchmark (`write-specs.py`), not generated by `clify add`; the race in [../race/](../race/README.md) measures generated specs.

Grading: every expected value must appear in the agent's final `ANSWER` line. Ground truth is recomputed with clify right before each run (`truth()` in `tasks.mjs`), so the grader and the clify racer share a tool. To check that this doesn't flatter clify, `node truth-check.mjs` recomputes all 20 truths without clify (plain `fetch` of each site's HTML or public JSON) and compares them with every recorded `truth.json`: **20 of 20 agree** ([results/truth-check.txt](results/truth-check.txt), run 2026-10-18). 2 trials per task per mode, 40 runs per mode. Results: `results/summary-main+hard+ui+ui2.json`; per run `runs/<tag>/<task>/<mode>-<n>/result.json` and the exact prompt.

| Mode (n=40) | Success | Median time | Median tokens | Total cost (list price) |
|---|---|---|---|---|
| browser, clicks only | 40/40 | 16.1 s | 79.4k | $4.12 |
| browser + page JS | 40/40 | 12.7 s | 50.4k | $2.29 |
| **clify** | **40/40** | **9.0 s** | **16.5k** | **$1.28** |
| agent + curl, no clify (run 2026-10-18, see below) | 40/40 | 7.5 s | 10.2k | $1.12 |

clify vs clicks-only browser: 1.8× faster, 4.8× fewer tokens, 3.2× cheaper. vs browser with page JS: 1.4× faster, 3.1× fewer tokens, 1.8× cheaper.

## Versus an agent with curl

**On these tasks curl beats clify.** Mode `curl` (2026-10-18 05:42–05:44 PT, AWS box, same model through the same Claude Code, 2 trials × 20 tasks): curl 40/40, 7.5 s / 10.2k tokens / $1.12 vs clify 40/40, 9.0 s / 16.5k / $1.28. clify's row is the earlier run above, so as a check clify was re-run on the same box at 05:48–05:54 PT: same box, same hour, the 14 tasks whose clify specs are in this repo: curl 28/28, 7.7 s / 10.2k tokens / $0.74 vs clify 28/28, 11.9 s / 18.2k tokens / $0.96 (`results/summary-clisame.json`). The other 6 tasks (GitHub, endoflife.date, Homebrew, Node.js) used specs from the earlier run's clify home, which is not in this repo (`write-specs.py` only patches the GitHub one), so they were not re-run; crates.io's spec came from `clify/proofs/sites/`.

Why: these are well-known public sites with documented JSON APIs (crates.io, hex.pm, GitHub, endoflife.date, Homebrew) or tiny static scraping sandboxes the model has memorised. The curl agent's median run is **one** tool call: a single curl + python script that fetches and parses the answer. The clify agent first reads `clify <site>` help, then calls the command (median 2–3 calls). By per-task median, curl was faster on 13 of 20 and used fewer tokens on 17 of 20. clify was faster on 7: clearly on endoflife-ubuntu-2204, ubuntu-lts-supported, webscraper-laptop-max, debian-nginx-bookworm and books-mystery-max, where curl first had to work out the page layout or the API (up to 4 calls, or one long script), and by under a second on two others.

So clify adds nothing when the model already knows the site's API. Where it does help is measured in the race ([../race/README.md](../race/README.md), mode D): signed-in dashboards with no documented API, sessions and CSRF tokens, and writes.

Truth for both curl-day tags was computed without clify (`node run.mjs --truth fetch`, the same fetch code as `truth-check.mjs`) and graded by the same `grade()`.

Run on a Linux box with Chromium (`npm install` and `npx playwright install chromium` in `../clify` first):

```bash
python3 write-specs.py          # installs the benchmark sites' specs into bench/.clify-home
ANTHROPIC_API_KEY=... node run.mjs --tasks <ids> --modes browser,browser-ui,cli --trials 2 --tag main
ANTHROPIC_API_KEY=... node run.mjs --truth fetch --modes curl --trials 2 --tag curl   # curl agent; truth without clify
node summarize.mjs main          # tags to combine, e.g. main hard ui ui2
```

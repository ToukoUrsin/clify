# clify demo film

[Remotion](https://www.remotion.dev) project for clify's 2-minute submission video. Every number on screen and in the voice-over is read from a data file built from the repo's own evidence (`race/`, `bench/`, `clify/proofs/`, `clify/test/`, `mcp/demo/`, `agent/`); the headline figures come from `scripts/counts.mjs --print`, the same derivation that checks the README, and `scripts/import-sub.mjs` fails if a proof file disagrees with it.

- **Submission cut:** `src/Submission.tsx` (scenes in `src/sub/`), 119.4 s, 1080p30, in two versions: composition `Submission` (v10, with the 20-task bench beat) and `SubmissionV11` (v11, the same film with that beat replaced by the race's third lane: an agent with curl and the same saved sessions, race mode D). Final file: [`out/clify-submission-v11.mp4`](out/), the cut `final.json` names (`scripts/export-public.sh` ships only that one and points the README links at it). Script, shot list and the source file of every number: [SUBMISSION.md](SUBMISSION.md).
- **Earlier 72 s cut:** composition `Primary` (`src/Primary.tsx`, scenes in `src/scenes/`), built on the `bench/` benchmark. Compositions `Main` / `MainVO` (about 2 min, adds the verified-site wall) and `Teaser` are kept as options.

## Render

Rendering is heavy (Chromium + ffmpeg, several GB of RAM); use a Linux machine or a cloud sandbox, not a laptop someone is working on.

```sh
cd film && npm ci && npx remotion browser ensure     # plus ffmpeg on PATH
node scripts/import-sub.mjs && scripts/stage-assets.sh    # data + footage from the repo
ELEVENLABS_API_KEY=... node scripts/make-sub-vo.mjs --music   # voice-over + music (only changed lines are re-synthesized)
./render-v10.sh vN                                         # composition Submission -> out/clify-submission-vN.mp4 (-16 LUFS) + out/review-vN/
./render-v11.sh v11                                        # composition SubmissionV11 -> out/clify-submission-v11.mp4 + out/review-v11/
```

The public repo leaves out the voice-over and music files (`public/audio/*.mp3`, see `OMITTED.md`); `make-sub-vo.mjs` regenerates the voice-over before a render.

`scripts/review.sh` and `scripts/contact.sh` make contact sheets (a frame every 2–3 s) for reviewing a render by eye.

## Where the numbers come from

| On screen | Source |
|---|---|
| Race (browser agent vs clify agent on signed-in dashboards, specs generated by `clify add`) | headline: `scripts/counts.mjs` `race.generated` (ratio of means + paired per-run mean, as in the README); run on screen: `race/results/generated-<run>.summary.json`; footage `race/artifacts/accounts-4x.mp4` + `accounts-realtime.mp4` (`film/race.json` picks the run; it must be in `race/results/accounts-modes.json`) |
| 20-task benchmark, one line (easy public read-only tasks, three modes, n=40 each; v10 cut) | `bench/results/summary-main+hard+ui+ui2.json`, ratios checked against `bench/README.md` |
| Agent + curl with the same saved sessions (race mode D; v11 cut) | `scripts/counts.mjs` `curl.race` (= README “Versus an agent with curl”, `race/results/curl-modes.json`, 2 runs, D and clify the same runs); the browser bar is the round 5 mean (`race.generated`) |
| `clify add` on ycombinator.com | `clify/proofs/sites/ycombinator.add-report.json`, log `evidence/sweep/` |
| Cold start | `clify/proofs/cold-start.md` |
| Agent signups (signed in, logged in, email-verified), SMS code | `clify/test/accounts/results.md`, logs `evidence/accounts/` |
| CAPTCHA → ask a human | `clify/test/ask/1-signup-skip.md`, the ask's own record `evidence/ask/` |
| Hosted MCP on Manufact, four clients (Claude Code shown large from its transcript) | `mcp/demo/out/*.mp4`, `mcp/demo/transcript-*.md`; sites / commands / tools (3 core + 4 shortcuts) / tool-list tokens from `counts.mjs` (= `mcp/demo/tool-tokens.json`) |
| Always-on email agent on InstaBox | `agent/proofs/video/clify-agent.mp4`, `agent/README.md`, `agent/proofs/` |
| Blaxel sweep (one sandbox per site) | `clify/proofs/sites-blaxel.md` (checked against `counts.mjs` `sweep.blaxel`) |
| Verified-site wall | `clify/proofs/wall.json` (= `counts.mjs` `wall`, `sweep.all`); blank (<3 KB) screenshots are dropped so those tiles show name + count |

## Honesty notes

- Race and benchmark runs are real Claude Code runs (`claude-opus-5-5`); both racers in a run use the same model, prompt and accounts. The race slot replays one representative run (its cards say so) and leads with the ratio of means and the paired per-run mean over all generated-spec runs.
- The benchmark tasks are read-only lookups on public sites; the browser agents were correct too, the gain is time, tokens and cost.
- On those 20 public tasks an agent with plain curl beats clify (`bench/README.md`, “Versus an agent with curl”): the model knows those APIs. The v11 cut shows the signed-in race instead, where curl got the same saved sessions and clify still led (paired 1.5× faster, 1.8× cheaper, 2 runs).
- The agent's phone number is masked the same way on screen and in the public docs (`+1 209 ••• 1736`).
